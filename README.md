# FladSim

## シミュレーター選択（feature/three-stars）

トップページ `index.html` でフラッドとスリースターズを選択します。既存のフラッドは `flood.html` へ移しました。操作・ギミック処理は従来と同じです。`three-stars.html` はスリースターズ専用の練習画面です。

各ページから選択画面へ戻れます。選択画面ではPython・3Dランタイムを読み込まず、練習ページを開いたときだけ起動します。

## スリースターズ

`three_stars.py` がデバフ抽選、塔の抽選、タイムライン、正解の塔、土・風の被弾判定を処理します。描画・入力はフラッドと共通です。

- 9本の塔を半径0.54に等間隔で配置し、塔の円がボスのターゲットサークルと少し重なります。A（北）から時計回り20度の位置を起点にし、炎・雷・氷の各3本をグループで並べます。開始時に属性グループの順番だけをランダムにします。
- 各フェーズは各属性1本と追加1本の計4本を点灯。再点灯あり。追加属性は炎・雷・氷をランダムな順番で各1回ずつ選びます。
- 開始から0〜3秒はカウントダウン、3秒でデバフ付与（炎・雷・氷・なしから抽選）、6秒でフェーズ1、13秒に判定してフェーズ2、20秒に判定してフェーズ3、27秒に最終判定して終了。
- デバフ持ちは同属性の点灯塔の時計回りで次の点灯塔へ。基準属性が2本光った場合は後ろ側を基準にします。塔を踏むとその塔の属性にデバフが変わります。無職は各フェーズの重複属性の後ろ側の塔へ入り、無職のままです。
- 1・3回目は土（中心円範囲）か風（外周ドーナツ）。境界は塔の中心を通る半径0.54で、描画と被弾判定はPython側の同じ寸法を使います。点灯塔の内側／外側へ寄って処理します。予兆はボス周囲の岩／緑色の風の輪で表示し、着弾時に範囲を赤く表示します。
- 塔の半径は0.12、プレイヤー判定半径は0.025。塔内にプレイヤーの判定が収まり、ボス範囲に触れなければ成功。失敗後も3回まで続け、フェーズ別の失敗理由を表示します。
- デバフ・ボス攻撃を固定して練習することもできます。
- 各フェーズの判定時、判定対象の4本に属性色の高い円柱を0.8秒間表示します。次のフェーズの点灯とは別に表示し、最終判定後も消えます。一時停止中は演出も止まります。

参考：[ヤーン速報・絶妖星乱舞 P5](https://yan-flash.com/ultimate/yosei-ranbu#ult-phase-5)。配置寸法と時間はこのシミュレーターの練習用仕様です。

## エクサ（feature/exa）

選択画面から `exa.html` を開きます。`exa.py` が移動・連続円範囲・被弾を処理します。

- 1マーカーが北。縦は北→南、横は2マーカー側（東）→西へ進みます。縦横縦横縦横の6回で、各方向の3パターンを重複なくランダムに並べます。
- 3カウント後に最初の予兆。予兆は開始から3・5・7・9・11・13秒、各予兆の4秒後（7・9・11・13・15・17秒）に着弾開始。円は0.5秒間隔、各列10回、1着弾0.35秒です。複数の列が重なって進行します。
- 円半径0.32、移動間隔0.30。最初の円の中心は北／東の1.32に置き、円の内側の端がフィールドの接線に接する位置から開始します。初期カメラはAが画面上。進行方向は円内の大きな二重シェブロンで表示します。橙色は予兆、赤色と炎は着弾。通過中の途中侵入も被弾。速度・パターン調整UIはなく、PC・スマホの操作は共通です。

参考：[近接視点・絶ケフカ ひたすらエクサ](https://www.youtube.com/watch?v=2VyponGkJw8)。

## 3D版・共通操作

カメラはプレイヤーを中心に追従します。移動中もキャラクターが画面中央に留まり、回転・上下角度の調整もプレイヤーを中心に行います。

Three.jsで立体の円形フィールド、中央ボス、プレイヤー、マーカー、地面の予兆を描画します。Pythonのギミック処理・uv管理は共通です。WebGL 2対応のブラウザと、Three.js / Pyodide CDNへの接続が必要です。

カメラは斜め視点と真上視点を切り替え可能。左右のボタンで45度ずつ回転します。WASDはカメラから見た前後左右に移動します。スタート・再挑戦時はカメラの向きと角度も初期状態へ戻します。地面は3D空間で正円ですが、斜め視点では遠近により楕円状に見えます。範囲の形状・判定・1秒で消える予兆・攻撃時刻は2D版と同じです。

PCは左ボタンを押しながらドラッグしてカメラの回転・上下角度を調整できます。カメラ角度は30度からほぼ真上までに制限しています。クリック・タップ移動は廃止し、移動はWASDまたは移動スティックで行います。

スマホはゲーム画面左下のスティックでカメラ、右下のスティックで移動します。二本の指で同時操作が可能です。移動スティックは倒した量に応じて速度が変わり、指を離すと止まります。一時停止・再挑戦・フォーカス離脱・画面サイズ変更でも入力を解除します。スティックはタッチ機器または画面幅850px以下で表示されます。

仮想スティックの入力テストは `node tests/test_controls.cjs`、PCドラッグの入力テストは `node tests/test_pc_controls.cjs` で実行できます。

描画コードは `renderer3d.js` に分離しています。静的ホスティングで追加のビルドやサーバーは不要です。

FF14の直線範囲ギミックを練習する非公式のブラウザアプリ。Pythonで移動・時間・抽選・被弾判定を処理し、Pyodideでブラウザ内実行します。JavaScriptは入力・Canvas描画・Pythonの呼び出しを担当します。サーバー実行環境のないGitHub Pagesでも動きます。

## 開発

[uv](https://docs.astral.sh/uv/getting-started/installation/)をインストールして実行します。

```sh
uv sync --locked
uv run python serve.py
```

http://localhost:8000 を開きます。HTMLの直接オープンではPythonファイルを取得できません。初回はCDNからPythonランタイムを取得するためインターネット接続が必要です。

```sh
uv run python -m unittest discover -s tests -v
```

## 仕様

- 半径1の円形フィールド。12時から時計回りにA・2・B・3・C・4・D・1。
- ボスは中心固定。ターゲットサークル直径はフィールド直径の46%。
- 直線範囲の幅はフィールド半径の50%。帯の片側の縁が中心を通り、ターゲットサークルの半分を覆います。
- 角度は帯の法線を右方向0°・下方向90°とした画面座標。開始は45°・135°・225°・315°から均等に抽選。90°ずつ回転します。回転方向は初期設定でランダム、練習用に固定も可能。
- 開始時刻0・1・2・3秒に予兆。6・7・8・9秒に同じ順番で攻撃。判定は各攻撃の発生時点に1回、赤い表示は0.45秒残ります。
- プレイヤーの判定半径はフィールド半径の2.5%、移動速度は半径の55%/秒。帯の縁に判定半径が触れた場合も被弾します。
- WASDまたは移動スティックで、カメラ基準の上下左右へ移動。斜め移動の速度は正規化。
- 被弾後も4回まで練習継続。タブ切り替え・ウィンドウのフォーカス離脱で自動一時停止。
- 各予兆は出現から1秒で消えます。攻撃の発生時に赤い範囲を再表示します。ボスに接触しても移動を妨げません。

## GitHub Pagesへの公開

1. GitHubにリポジトリを作り、これらのファイルを`main`ブランチへpush。
2. リポジトリの **Settings → Pages → Source** を **Deploy from a branch** に設定。
3. ブランチを **main**、フォルダを **/(root)** にして **Save**（以降はmainへのpushで更新）。

URLは通常 `https://<ユーザー名>.github.io/<リポジトリ名>/`。相対パスを使用しているためリポジトリ名のサブパスに対応します。ローカルの `.github/workflows/pages.yml` をGitHubへ追加できる場合は、Sourceを **GitHub Actions** に変更することでテスト後に静的ファイルだけを公開する方式も使用できます。Workflowのpushには認証の `workflow` 権限が必要です。

## 構成

`game.py`: Pythonシミュレーション / `app.js`: 描画・入力 / `styles.css`: レスポンシブUI / `serve.py`: 開発用サーバー / `tests/`: ロジック検証。

外部ゲーム素材は使用していません。実際のFF14とはギミックの細部・速度・判定が異なる練習用実装です。

参考: [Pyodide公式ドキュメント](https://pyodide.org/en/stable/usage/quickstart.html)、[GitHub Pages公式ドキュメント](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)。
